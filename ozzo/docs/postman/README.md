# ozzo Postman Collection

End-to-end API testing collection for the ozzo microservice (account & subscription management).

## Files

- **`ozzo.postman_collection.json`** — The collection itself (generated by `build-collection.mjs`). Do not edit directly; edit `build-collection.mjs` instead and regenerate.
- **`build-collection.mjs`** — Collection builder script. Edit this to change requests, then run:
  ```bash
  node docs/postman/build-collection.mjs  # from ozzo/
  ```
- **`ozzo-local.postman_environment.json`** — Local dev environment (HS256, `http://localhost:3004`)
- **`ozzo-standalone-hs256.postman_environment.json`** — Standalone/Docker environment (HS256, `http://ozzo:3004`)

## Quick Start

1. **Import the collection and environment into Postman:**
   - Open Postman, click `Import` (top-left corner)
   - Drag-and-drop `ozzo.postman_collection.json`
   - Drag-and-drop `ozzo-local.postman_environment.json` (or the standalone variant)

2. **Configure the environment:**
   - Click the environment dropdown (top-right) and select `ozzo (local HS256)` or `ozzo (standalone HS256)`
   - Edit `jwtSecret` to match your `JWT_SECRET` (minimum 32 characters)
   - Verify `baseUrl` points to your running ozzo instance (default `http://localhost:3004`)

3. **Run the collection:**
   - Click the collection name, then the blue `Run` button (top-right)
   - Postman will execute all requests in order, chaining IDs through collection variables
   - Tests validate responses and populate variables for dependent requests

## Authentication

The collection uses **HS256 JWT tokens** signed by the collection's pre-request script.

- **Token variable:** `ownerToken` (set by pre-request script)
- **JWT claims:** `{ sub: 'user-alice', roles: [], iss: 'ozzo', iat, exp }`
- **How it works:**
  1. Pre-request script reads `jwtSecret` and `jwtIssuer` from the environment
  2. Signs an HS256 JWT with CryptoJS (no backend call needed)
  3. Injects the token into the `Authorization: Bearer <token>` header
  4. Every request is authenticated

To switch to **OIDC mode** (if your ozzo stack has `JWT_JWKS_URI` configured):
- Set environment variable `authMode` to `oidc`
- Set `oidcTokenUrl`, `oidcClientId`, `oidcClientSecret`, and `ownerOidcScope`
- The pre-request script will fetch tokens from your OIDC provider instead of signing locally

## Request Flow

The collection runs requests in this order, creating test data as it goes:

### 1. Users
- **POST /users** — Create a new user with profile (address, DOB, next of kin, contact person)
- **GET /users/:id** — Retrieve the user
- **GET /users/:id/profile** — Get profile with bank accounts and total balance
- **PATCH /users/:id** — Update user fields

### 2. Bank Accounts
- **POST /users/:id/accounts** — Link a checking account
- **GET /users/:id/accounts** — List all accounts
- **GET /users/:id/accounts/:accountId** — Get a specific account
- **PATCH /users/:id/accounts/:accountId** — Update account type (checking → savings)
- **DELETE /users/:id/accounts/:accountId** — Close the account

### 3. Wallet Sync
- **GET /users/:id/wallet** — Sync wallets from zuma wallet-service (cached in Redis)

### 4. Operations
- **GET /healthz** — Health check
- **GET /readyz** — Readiness check (confirms all dependencies are ready)

## Test Assertions

Each request includes a `Tests` tab with assertions:
- HTTP status code (201, 200, 204, 401, 404, etc.)
- JSON schema validation (checks required fields and types)
- Business logic checks (e.g., "account type was updated to savings")
- Variable chaining (extracts IDs for dependent requests)

View test results in the `Test Results` tab after running the collection.

## Variables

### Environment Variables (set per environment)

| Variable | Default | Purpose |
|---|---|---|
| `baseUrl` | `http://localhost:3004` | Root URL of ozzo service |
| `jwtSecret` | (set manually) | Signing key for HS256 tokens (≥32 chars, must match `JWT_SECRET`) |
| `jwtIssuer` | `ozzo` | JWT issuer claim |
| `jwtAudience` | (empty) | JWT audience claim (optional; set if your ozzo requires it) |
| `jwtTtlSeconds` | `300` | Token lifetime (seconds) |
| `authMode` | `hs256` | Auth mode: `hs256` or `oidc` |
| `oidcTokenUrl` | (empty) | OIDC token endpoint (when `authMode=oidc`) |
| `oidcClientId` | (empty) | OIDC client ID |
| `oidcClientSecret` | (empty) | OIDC client secret |
| `oidcHostHeader` | (empty) | OIDC Host header (some IDPs require it) |
| `ownerSub` | `user-alice` | JWT subject (user ID claim) |
| `ownerOidcScope` | `ozzo-user` | OIDC scope for user tokens |

### Collection Variables (populated at runtime)

| Variable | Set by | Purpose |
|---|---|---|
| `ownerToken` | Pre-request script | Current bearer token (refreshed before every request) |
| `userId` | POST /users response | ID of the created test user |
| `username` | POST /users response | Username for verification tests |
| `accountId` | POST /users/:id/accounts response | ID of the linked bank account |
| `accountNumber` | POST /users/:id/accounts response | Account number for reference |

## Editing the Collection

To add, remove, or modify requests:

1. Edit `docs/postman/build-collection.mjs` (the source of truth)
2. Add/modify items in the `items` array
3. Regenerate the JSON file:
   ```bash
   node docs/postman/build-collection.mjs  # from ozzo/
   ```
4. Reimport `ozzo.postman_collection.json` into Postman

Example: adding a new request

```javascript
items.push({
  name: 'My Folder',
  item: [
    {
      name: 'GET /some/endpoint',
      event: [{ listen: 'test', script: { type: 'text/javascript', exec: ["pm.test('Status', () => pm.response.code === 200);"] } }],
      request: {
        auth: { type: 'bearer', bearer: [{ key: 'token', value: '{{ownerToken}}' }] },
        method: 'GET',
        url: { raw: '{{baseUrl}}/some/endpoint', protocol: 'http', host: ['{{baseUrl}}'], path: ['some', 'endpoint'] },
      },
      response: [],
    },
  ],
});
```

## Common Issues

### 401 Unauthorized on all requests
- **Cause:** `jwtSecret` is not set or does not match `JWT_SECRET` in ozzo
- **Fix:** Set the environment variable `jwtSecret` to the same value as ozzo's `JWT_SECRET`

### Connection refused (http://localhost:3004)
- **Cause:** ozzo service is not running
- **Fix:** Start ozzo with `npm run dev` (from `ozzo/`) and wait for the server to be ready

### Tests fail with "response is undefined"
- **Cause:** Request timed out or failed before a response arrived
- **Fix:** Check the `Response` tab; if empty, see "Connection refused" above

### Token expires mid-run
- **Cause:** Collection run takes longer than `jwtTtlSeconds`
- **Fix:** Increase `jwtTtlSeconds` in the environment (e.g., to 3600 for 1 hour)

## Generating OpenAPI from Live Service

To extract the live OpenAPI spec from a running ozzo instance:

```bash
curl http://localhost:3004/openapi.json > ozzo-openapi-generated.json
```

The spec is generated dynamically by `@fastify/swagger` from the JSON schemas in `src/api/schemas/index.ts`.
