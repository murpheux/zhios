# @gnee/ios

iOS shell for the Zuma wallet app (Expo SDK 58, React Native 0.88,
React 19.3, TypeScript). All screens, navigation and business logic live in
[`@gnee/mobile-ui`](../../packages/mobile-ui) (`<ZumaMobileApp>`) and
[`@gnee/api-client`](../../packages/api-client). `App.tsx` does only three
things: resolve the gateway URL, read the token from `expo-secure-store`,
and render `<ZumaMobileApp>`. Setup is identical to [`@gnee/android`](../android).

## Run

```bash
cd gnee/apps/ios
cp env.example .env   # EXPO_PUBLIC_ZUMA_GATEWAY_URL (default http://localhost:3003/graphql)
npm install           # from gnee/ (workspaces)
npm run ios         # first run generates the native ios/ project via expo prebuild
```

The gateway URL is resolved in this order:

1. `process.env.EXPO_PUBLIC_ZUMA_GATEWAY_URL` (inlined by Metro)
2. `extra.zumaGatewayUrl`, which `app.config.ts` also fills from that env var for EAS builds
3. `app.json`'s `extra`
4. the built-in fallback `http://localhost:3003/graphql`

Requires the zuma `graphql-gateway`. Start it with `../zuma/scripts/dev-up.sh --full`.

## Auth

The app reads a JWT from `expo-secure-store` under the key `zuma_jwt`. Until
a login screen is added, seed it manually for local testing, e.g.
`SecureStore.setItemAsync("zuma_jwt", token)` from a debug action.

## Idempotency keys (send flow)

Every send needs an idempotency key generated by a CSPRNG. Hermes has no global `crypto`,
so `App.tsx` passes `createIdempotencyKey={() => Crypto.randomUUID()}` from `expo-crypto` to
`<ZumaMobileApp>`. If that prop is removed, the send screen disables sending instead of
falling back to `Math.random`.

## Lint / Typecheck / Test

```bash
npm run lint         # biome lint .
npm run typecheck    # tsc --noEmit
npm test             # jest-expo unit test (App.test.tsx); screen tests live in packages/mobile-ui
```

E2E uses Detox and needs a real iOS Simulator build (macOS + Xcode):

```bash
npx expo prebuild --platform ios   # generates ./ios (git-ignored)
npm run e2e:build                   # xcodebuild, via .detoxrc.js
npm run e2e:test                    # runs e2e/*.e2e.js
```

**Detox status:** `@config-plugins/detox` isn't in the manifests yet. Before
relying on `expo prebuild` for Detox builds, add it as a dev dependency and
list it under `plugins` in `app.json` (`"plugins": ["@config-plugins/detox"]`).

## Devcontainer

`.devcontainer/devcontainer.json` opens the whole `gnee/` workspace in a Linux Node 22 container. It covers editing, `npm run lint`, `typecheck` and `npm test`. It **cannot** build or run iOS: `expo run:ios`, `xcodebuild` and the Simulator need macOS + Xcode.

## Deploy

Docker, Swarm and Kubernetes don't apply to a native app. It ships as a
signed binary through App Store Connect via EAS Build/Submit:

```bash
../../scripts/deploy-mobile.sh ios production
```

Build profiles are in `eas.json` (`development` / `preview` / `production`).
The App Store Connect API key is used for non-interactive `eas submit`. The key comes from 1Password (`op read`), is written to a 0600 temp
file only after `eas build`, and is deleted on exit. See
`scripts/deploy-mobile.sh` and `infrastructure/README.md`.

## Observability (New Relic Mobile)

`@gnee/mobile-ui` starts the New Relic Mobile agent (`newrelic-react-native-agent`) from `<ZumaMobileApp newRelic={...}>`. `App.tsx` reads `EXPO_PUBLIC_NEWRELIC_ENABLED`, `EXPO_PUBLIC_NEWRELIC_APP_TOKEN` and `EXPO_PUBLIC_APP_ENV` (see `env.example`). Use the **mobile application token** for this platform's app in New Relic, not the browser license key. Set it as an EAS environment variable rather than committing it.

- **Native module:** the agent needs native code, so it does not run in Expo Go. Use a development build (`eas build --profile development`, or `expo prebuild` and then `expo run:*`). Follow New Relic's React Native/Expo setup for the platform plugin (iOS pod, Android Gradle plugin) before the first native build. Without the module the app runs normally and logs a warning.
- **Automatic:** native crashes, JS exceptions, unhandled promise rejections, HTTP timings.
- **React errors:** `ErrorBoundary` in `@gnee/mobile-ui` reports to `recordError` and offers a retry.
- **GraphQL and network errors:** `@gnee/api-client` reports failures (operation, code, status; no variables or tokens).
- **Custom events** (`ZumaMobileAction`): `wallet_created`, `transaction_sent`. Screens can add their own with `useNewRelic()`.
