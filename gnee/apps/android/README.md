# @gnee/android

Android shell for the Zuma wallet app (Expo SDK 58, React Native 0.88,
React 19.3, TypeScript). All screens, navigation and business logic live in
[`@gnee/mobile-ui`](../../packages/mobile-ui) (`<ZumaMobileApp>`) and
[`@gnee/api-client`](../../packages/api-client). `App.tsx` does only three
things: resolve the gateway URL, read the token from `expo-secure-store`,
and render `<ZumaMobileApp>`. Setup is identical to [`@gnee/ios`](../ios).

## Run

```bash
cd gnee/apps/android
cp env.example .env   # EXPO_PUBLIC_ZUMA_GATEWAY_URL (10.0.2.2 reaches host localhost from the emulator)
npm install           # from gnee/ (workspaces)
npm run android         # first run generates the native android/ project via expo prebuild
```

The gateway URL is resolved in this order:

1. `process.env.EXPO_PUBLIC_ZUMA_GATEWAY_URL` (inlined by Metro)
2. `extra.zumaGatewayUrl`, which `app.config.ts` also fills from that env var for EAS builds
3. `app.json`'s `extra`
4. the built-in fallback `http://10.0.2.2:3003/graphql`

Requires the zuma `graphql-gateway`. Start it with `../zuma/scripts/dev-up.sh --full`.

## Auth

The app reads a JWT from `expo-secure-store` under the key `zuma_jwt`. Until
a login screen is added, seed it manually for local testing, e.g.
`SecureStore.setItemAsync("zuma_jwt", token)` from a debug action.

## Idempotency keys (send flow)

Every send needs an idempotency key generated by a CSPRNG. Hermes has no global `crypto`,
so `App.tsx` passes `createIdempotencyKey={() => Crypto.randomUUID()}` from `expo-crypto` to
`<ZumaMobileApp>`. If that prop is removed, the send screen disables sending instead of
falling back to `Math.random`.

## Lint / Typecheck / Test

```bash
npm run lint         # biome lint .
npm run typecheck    # tsc --noEmit
npm test             # jest-expo unit test (App.test.tsx); screen tests live in packages/mobile-ui
```

E2E uses Detox and needs a real Android Emulator build:

```bash
npx expo prebuild --platform android   # generates ./android (git-ignored)
npm run e2e:build                   # gradlew assembleDebug, via .detoxrc.js
npm run e2e:test                    # runs e2e/*.e2e.js
```

**Detox status:** `@config-plugins/detox` isn't in the manifests yet. Before
relying on `expo prebuild` for Detox builds, add it as a dev dependency and
list it under `plugins` in `app.json` (`"plugins": ["@config-plugins/detox"]`). On Android the plugin also wires the instrumentation runner and the `androidTest` source set that `.detoxrc.js` expects.

## Devcontainer

`.devcontainer/devcontainer.json` opens the whole `gnee/` workspace in a Node 22 container with the Android SDK and JDK 17, so `expo prebuild --platform android` and `./gradlew assembleDebug` work. There's no emulator (no KVM), so use a physical device over `adb`, or build APKs here and test them elsewhere.

## Deploy

Docker, Swarm and Kubernetes don't apply to a native app. It ships as a
signed AAB through Google Play via EAS Build/Submit:

```bash
../../scripts/deploy-mobile.sh android production
```

Build profiles are in `eas.json` (`development` / `preview` / `production`).
The Google Play service account JSON is exposed at `google-service-account.json` (the path `eas.json` expects) only for the duration of `eas submit`. The key comes from 1Password (`op read`), is written to a 0600 temp
file only after `eas build`, and is deleted on exit. See
`scripts/deploy-mobile.sh` and `infrastructure/README.md`.
